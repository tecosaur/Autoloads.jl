#+title: Autoloads
#+author: tecosaur

Autoloads lets you *use packages at the REPL without loading them first*.

When you run code that uses a name such as ~@b~, ~DataFrame~, or an
unqualified ~@spawn~, and an autoload package provides that name, Autoloads
loads the package just before the code runs. Add the packages once, and forget
about them.

** Setup

Add Autoloads to your global environment, and load it from your startup file:

#+begin_src julia-repl
pkg> add Autoloads
#+end_src

#+begin_src julia
# ~/.julia/config/startup.jl
using Autoloads
#+end_src

The first ~pkg> autoloads add~ creates the ~autoloads~ environment (as
~pkg> autoloads init~ does), a workspace member of your global environment.
It is never left on the ~LOAD_PATH~. On a new Julia version, the first REPL
session sets it up in the background from the previous version's, packages
and settings included.

** Adding packages

#+begin_src julia-repl
pkg> autoloads add About Chairmarks DataFrames

julia> @b sum(rand(1000))   # loads Chairmarks
694.333 ns (3 allocs: 7.883 KiB)

julia> about(sum)           # loads About
sum (generic function with 10 methods)
 Defined in Base(8) extended in MPFR(1) and GMP(1).
#+end_src

Autoloads only acts on names that are undefined and not locally bound. If the
active project provides an autoload package, it is loaded from there. The
active project's dependencies autoload too, as does the project itself when
it is a package. Indexing and precompilation happen in the background.

A name that several autoload packages provide is not autoloaded, unless they
all re-export it from one package (as ~fit~ from StatsAPI, by both StatsBase
and Distributions): it then comes from whichever of them is loaded first.

Autoloadable names also tab-complete, and an ~UndefVarError~ lists the
packages that provide the name.

The full set of commands is:

#+begin_example
pkg> autoloads init
pkg> autoloads add [-g] pkg ...
pkg> autoloads rm [-g] pkg ...
pkg> autoloads up [-g] [pkg ...]
pkg> autoloads status [pkg ...]
#+end_example

~autoloads status~ lists the autoload packages and the names more than one of
them claims; given packages, it lists the names each offers and which of them
autoload it.

~autoloads add~ takes names, git URLs (=url#rev= for a revision), or paths of
directories to develop; ~add Foo~ develops =./Foo= if that directory exists.
When ~autoloads init~ carries packages over from an older Julia version,
developed and git-sourced ones keep their source. ~autoloads up~ updates
the autoload packages together with the global environment's own, as does a
plain ~pkg> up~ with the global environment active.
With ~-g~ (~--global~), a change is also made to every other Julia version
that has an autoloads environment, each resolving it in the background when
it next starts a REPL session.

** Settings

Settings live in ~[preferences.Autoloads]~ in the global environment's
=Project.toml= or =LocalPreferences.toml=.

| Key                        | Default        | Meaning                                                       |
|----------------------------+----------------+---------------------------------------------------------------|
| ~stdlib~                   | ~true~         | Also autoload names from the standard libraries               |
| ~project~                  | ~true~         | ~false~ or a list: autoload the active project's dependencies |
| ~precompile~               | ~"background"~ | ~"lazy"~ indexes without precompiling                         |
| ~bindings~                 | ~"all"~        | ~"used"~ loads only the names used                            |
| ~log~                      | ~false~        | ~true~ announces each autoload with an info line              |
| ~up_hook~                  | ~true~         | ~false~: ~pkg> up~ leaves the autoload packages alone         |
| ~packages.<Name>.skip~     | ~[]~           | Names not to autoload                                         |
| ~packages.<Name>.only~     | unset          | Autoload only these names                                     |
| ~packages.<Name>.bindings~ | global setting | Per-package ~bindings~                                        |

For example, to have ~@spawn~ come from ~Threads~ rather than ~Distributed~
(both provide it, so by default neither autoloads it):

#+begin_src toml
[preferences.Autoloads]
packages.Distributed = {skip = ["@spawn"]}
#+end_src

** Limitations

+ Code built with ~@eval~ is not seen.
+ Candidate statements are macroexpanded twice.
+ This works at the REPL only, not in IJulia or scripts.
+ Extensions of autoloaded packages need ~@v#.#~ on the ~LOAD_PATH~.
